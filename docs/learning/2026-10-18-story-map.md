# Story map and per-stage leaderboards (L5)

The STORY button now opens a map: one island per stage on a notebook page.
Reached islands are shaded, show a sketch of their world and your best
score; a flag marks a beaten boss; your ship waits on the furthest island;
the rest are a dashed "?". Tapping a reached island opens that stage's
world board. PLAY always starts a run at island 1 (owner's pick: no
practice mode, arcade rules stay).

Built in four subgoals, explained in that order.

### 1. Progress that survives a reload
**What changed:** `services/storyProgress.ts` keeps `{ furthest, best[],
bestRun }` in localStorage. `GameScene` records a stage when it ends
(cleared or not) and a run when it ends.
**Pattern:** functional core, imperative shell (ARCHITECTURE.md §2.14):
`mergeLevel` / `mergeRun` / `islandState` are pure and unit-tested;
`recordLevel` / `recordStoryRun` only read, merge and write.
`parseProgress` cleans what comes back from storage (a hand-edited value
can't break the map).
**Why this way:** the unlock rule ("clearing stage N opens N+1, a worse
run never closes anything") is the part that can be wrong, and it is now
tested without a browser (`storyProgress.test.ts`).
**Alternatives considered:**
- One localStorage key per stage (like `masteryStats`): many keys for one
  thing, and no single place to check it's sane.
- Saving inside `GameScene`: the rule would only be testable by playing.
**How to change it later:** a new field (e.g. stars per stage) = add it to
`StoryProgress`, `mergeLevel` and `parseProgress`, plus a test.
**Verified by:** 5 unit tests; an ace bot cleared level 1 in the browser and
the map showed island 1 flagged with its score and the ship on island 2.

### 2. The map
**What changed:** `scenes/StoryMapScene.ts` draws the page; island doodles
and the trail are in `renderDoodle/storyMap.ts`; positions and inks are
`STORY_MAP` in `config/tuning/story.ts`.
**Pattern:** pre-rendering (CONCEPTS: drawn once with `drawFrames`, then
copied), the same way the menu's ship picker works. Content as data: the map
reads `LEVELS` for built stages and `STORY.STAGES` for planned ones, so a
level merged from another chat shows up with no map change.
**Why this way:** the map is mostly static pictures; drawing them once at 2×
keeps it sharp and cheap on phones.
**Alternatives considered:**
- Drawing on the DoodleWorld canvas: that view belongs to play (and hides
  outside GameScene).
- A DOM page over the canvas: crisp, but a second UI system for one screen.
**How to change it later:** move an island = `STORY_MAP.SPOTS`; a world's
sketch = its function in `WORLDS` (`storyMap.ts`).
**Verified by:** screenshots at 0, 1 and 10 stages reached; the "?" and the
ship size were fixed after the first look (the ship texture cache ignored
size: `shipIconFrames` keys now include it).

### 3. One board per stage, behind the same gate
**What changed:** `supabase/story-boards.sql` adds `scores.level` (0 Endless,
1–10 stage, 99 run) and a board to every match ticket; `leaderboard.ts`
takes a `board` everywhere (`startMatch`, `submitScore`, `getTop`,
`getRank`) and keeps one open ticket per board.
**Pattern:** backward-compatible migration (ARCHITECTURE.md §2.16, new).
**Why this way:** the live game keeps working during the gap between the
SQL running and the new game being deployed.
**Alternatives considered:**
- A `stage_scores` table: every function twice (owner picked the column).
- One ticket for the whole run: a stage's score could then be posted with
  the run's ticket to any board; tickets per board keep the gate tight.
**How to change it later:** a new kind of board = a number in
`LEADERBOARD`, and maybe its cap in `board_score_cap`.
**Verified by:** tsc; the client without credentials (boards say "World
scores are offline" and still show your best). **Not verified:** the SQL
against a real database (not applied: it needs the owner's yes).

### 4. Ending a story run
**What changed:** `StoryRun` carries `levelScores`. When a run ends,
`GameScene.leaveGameOver` sends one name entry with a list of boards (the
run's total first, then each stage); `NameEntryScene.submitAll` submits them
in turn and the board screen shows the run board plus one line of stage
ranks; BACK returns to the map.
**Why this way:** typing initials once per stage would interrupt the run.
**Alternatives considered:** submitting each stage when it ends with the
last-used initials: no typing, but scores could go up under a name the
player never confirmed.
**Verified by:** in the browser, the name entry → "STORY RUNS" board → map
path; golden master unchanged (Endless and battles untouched).
