# Level 5, THE DARK CAVE (2026-10-18)

Story level 5 built as its own level, the way level 1 is built: rules in
`src/config/levels/cave.ts`, looks in `src/renderDoodle/levels/cave.ts`,
creature rules in `src/objects/caveTraits.ts`, the boss in
`src/objects/caveTroll.ts`, a test in `src/sim/storyCave.test.ts`. Design
and bot numbers: `docs/SOLO_MODES_DESIGN.md` "Level status".

Subgoals, in the order the change was built:
1. give abilities a way to change how their alien moves (`pace`);
2. the bat and the glowworm as traits;
3. the troll as a Boss subclass whose numbers depend on a beam;
4. the beam on screen (`BossLook.under`);
5. tune with bots.

### 1. `Ability.pace`: a hook that changes the kind's movement
**What changed:** `Alien.advance` now asks its ability how many ms of its
kind's pattern to run this step: `delta = ability.pace(this, delta)`. The
base `Ability.pace` returns `delta`, so every existing alien moves exactly
as before (golden master unchanged).
**Pattern:** hook with a default (template method, ARCHITECTURE.md §2.7):
the base class calls a method that does the normal thing; a subclass
overrides just that step.
**Why this way:** the bat must stand still (return 0), then drop slower
(return `delta * 0.65`); the troll must freeze in light and speed up per
answer (`delta * (1 + 0.12 * answers)`). One number covers hold, slow and
fast, and the kind's own pattern still does the moving, so nothing about
darters, lumberers or strafers is copied.
**Alternatives considered:**
- A new movement kind "bat" in `MONSTERS` — lost: `AlienKind` is used by
  many tables (inks, recipes, two-ball weights, boxes), so a kind is a big
  shared change while four other levels are being built at once.
- The pond chat's `Ability.steer` (script moves with `glideTo`/`hold`) —
  it can hold an alien but not make its pattern run faster or slower, which
  the troll's rage needs. The two don't overlap; keep both when merging.
- Per-alien speed fields (`patrolSpeed`, `diveSpeed`…) on `AlienConfig` —
  lost: one field per need, and the timing (hang → wake → drop) would still
  need code somewhere.
**How to change it later:** a new creature that moves "like X but…"
overrides `pace` in its trait (see `Roost` and `Glow`).

### 2. Bat and glowworm: traits
**What changed:** `Roost` keeps its own little timeline (fly → hang → wake →
drop). It lets the strafer fly in, then returns 0 while hanging, sets
`alien.mode = "windup"` to wake (the view's shake and the bots' "about to
dive" come for free), then `"dive"` and returns `delta * DROP_PACE` with a
sideways flutter. `Glow` reuses `blinkCover` (the Blinker's rhythm) and
moves at 60% (it hides its numbers: owner's balance rule).
**Why this way:** both are plain Abilities, so they plug into
`SpeciesDef.TRAIT` with one line each in `TRAITS`; tuning numbers live in
the level's own file (`BAT`, `GLOW`), so no shared tuning file changes.

### 3. CAVE TROLL: a Boss read by lamplight
**What changed:** `CaveTroll extends Boss` and overrides two hooks:
`update` (move the beam; cover = 0 while its whole ball row is inside the
beam, 1 outside, fading at the edge) and `pace` (0 while lit, faster after
each answer). Everything else (HP, staggering away after an answer,
retreating after reaching the ship) is the base Boss. Swarm now calls
`update(dt, alien)` so the troll knows where it is.
**Why this way:** bots and the view already read `ability.cover`, so the
"can't read it in the dark" rule needed no bot or view change.
**Alternatives considered:**
- A beam from the ship — lost: the ship only slides toward a target, so the
  player can't aim it; the light would feel random.
- A pendulum swing (sine) — lost: it lingers at the ends and rushes through
  the middle, so a troll in the middle would be lit far less. A triangle
  wave moves at a steady speed: every spot gets the same time per pass.
**How to change it later:** `TROLL_LAMP` in `config/levels/cave.ts` (beam
width, sweep, period, rage).

### 4. The beam on screen: `BossLook.under`
**What changed:** a boss look may draw on the page before the aliens
(`under(ctx, boss, alpha)`); DoodleWorld calls it, and the cave draws a pale
cone with dashed pencil edges from the beam angle the sim reports.
**Why this way:** generic (a shadow, a puddle…), a few lines in
DoodleWorld, and the view still only reads sim state.

### 5. Tuning with bots
At the planned d 0.5 → 0.65, pilots cleared 1/20 (darter glowworms caused
most hits) and the troll knocked out pilots who were busy with minions when
the beam passed. Glowworms at 60%, d 0.45 → 0.6, a wider (26°) and slower
(7 s) beam and a slower troll (0.3) gave rookie 2/20, pilot 18/20, ace 20/20
(level 1: 16/20/20).

**Verified by:** `npx tsc --noEmit`, `npm test` (golden master unchanged,
`storyCave.test.ts`: every creature appears, no box overlaps, bats hang
still then drop, glowworms go dark and light up, the troll is readable only
in the beam and doesn't move while lit, the boss takes 6 answers, an ace
clears 4+ of 5 seeds), `npm run build`, and the level played by a pilot bot
in headless Edge (screenshots).
