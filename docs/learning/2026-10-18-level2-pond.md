# Level 2, THE POND: creatures that move themselves (2026-10-18)

How story level 2 was built, and the three small rules it added for every
later level. Files: `src/config/levels/pond.ts` (rules data),
`src/objects/pondCreatures.ts` (the pond's traits and boss),
`src/renderDoodle/levels/pond.ts` (looks), `src/sim/pond.test.ts`.

### A creature that moves itself: the `steer` hook
**What changed:** `Ability` got a fourth hook, `steer(alien, fieldDelta)`.
`Swarm.step` calls it for every alien right before moving it (not for the
held target). The pond's dragonfly (`Dart`), duck (`Dive`), frog (`Hop`)
and the `BigFrog` use it to call `alien.glideTo` / `alien.hold`.
**Pattern:** hook / template method — the base class calls an empty method
at a fixed moment; a subclass fills it in. (ARCHITECTURE.md §2.7)
**Why this way:** a dragonfly that zips and hovers needs to move itself,
but the old `update(delta)` gets no alien and runs on *real* time (so a
Blinker blinks through a freeze). Movement driven by real time would keep
darting while the player has FREEZE on. `steer` gets the field's delta,
so freezes and SLOW hold it like any other move.
**Alternatives considered:**
- Pass the alien to `update` — still real time, so FREEZE wouldn't stop a
  dart; and changing `update`'s meaning would touch every ability.
- A new movement kind per creature in `Alien.advance` — a bigger shared
  change in a file every level chat touches, and kinds also drive Endless.
**How to change it later:** a new self-moving creature = an Ability class
with a `steer` method + one line in `TRAITS` (`objects/traits.ts`).
**Verified by:** golden master unchanged (no Endless/battle ability uses
`steer`), `pond.test.ts` checks dragonflies hover mid-dive and ducks hide
their numbers.

### More balls in a level: `LevelDef.MAX_BALLS`
**What changed:** `LevelDirector.difficulty` uses the level's `MAX_BALLS`
when it has one (pond: 4) instead of what the d range gives (2 at d < 0.5).
**Why this way:** the design says level 2 is "sums with 3–4 balls", while
its speed should stay gentle. Ball count and speed were tied to the same
d; this unties only the ball count, only for levels that ask.
**Alternatives considered:** raising the d range (faster aliens too:
rookies cleared 0/20 at d 0.2 → 0.35); a per-level ball-count weight table
(more shared code than needed yet).

### Compact big sums: the `cluster` layout
**What changed:** `BALL_LAYOUTS.cluster` + two cases in `Alien.boxFor` /
`ballOffset`: balls in rows of 2 going up from the body. The frog's spots.
**Why this way:** a 4-ball row is 78 px wide; 2 × 2 is ~55 px and reads as
spots on a back. The box follows the layout, so readability still holds.
**How to change it later:** spacing is `GAP_X` / `GAP_Y` in
`config/tuning/monsters.ts` (raised from 21/19 to 22/20 after the rings
looked crowded in the browser).

### The level itself (data + looks)
- Goldfish (darter): numbers are bubbles (chain layout), schools of 3 on
  15% of spawns. Dragonfly (strafer): eyes are numbers, darts down.
  Frog (lumberer, 3–4 balls): sits 250 ms longer per spot (owner's rule:
  harder to solve = slower). Duck (drifter bonus): dives, numbers hidden.
- BIG FROG (`leap`): 6 answers of 4 balls; leaps in, then sits 1.9 s,
  croaks 0.7 s (it sets `alien.mode = "windup"`, which the view already
  shakes and bots already treat as danger), leaps 40 px down and 60 px
  across. ~13 px/s, slower than the mole (owner's rule: more answers →
  slower).
